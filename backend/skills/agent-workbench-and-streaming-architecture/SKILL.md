# Agent Workbench and Streaming Architecture

Use this skill when designing, building, or auditing high-performance AI agent workbenches, interactive chat timelines, streaming Markdown renderers, composer docks, and terminal execution surfaces (achieving parity with Anara Desktop, Anara Coding Agent, and Cursor).

## Core Architectural Invariants

### 1. ScaffoldRow vs Card-itis on Conversational Scaffolding
- **Flat In-Flow Scaffolding Rows (Anara Desktop Parity):** Never wrap conversational scaffolding items (thinking disclosures, tool execution lines, file edit diffs, task checklists, exploration summaries) in heavy rounded rectangle cards (`rounded-lg bg-[#070b14]/75 border border-white/[0.08] shadow-[...] backdrop-blur-xl`). In Tier-1 agent workbenches, scaffolding items at rest are **scaffold lines** (`ScaffoldRow`): clean, quiet, single-line text items that sit directly in the transcript flow (`● Thinking (1.2s) ›`, `● Thought for 1.2s ›`, `● Edit file.ts +12 -3 ›`, `● Run npm test (0.4s) ›`).
- **Expandable Inset Accordions:** Inset disclosure panels open strictly upon user click beneath the scaffold line (e.g. diff gutter table, terminal output box, or flush thinking text with `border-l border-white/10 pl-3`).
- **Direct Canvas Assistant Stream:** Assistant narrative text must flow directly on the dark canvas (`text-slate-200 text-[13.5px] leading-relaxed font-sans`). Reserve bordered cards strictly for interactive question forms and standalone document artifacts.

### 2. Composer Dock, Backdrop Blur Isolation & Input Ergonomics
- **Decoupled Backing Layer for Backdrop Blur (Anti-Typing Jitter):** Keep `backdrop-filter` strictly OFF the hot editable surface (`textarea` or contenteditable container) per Anara Desktop `composer-dock.ts`. Applying backdrop blur directly on the editable element forces the browser to re-composite and re-blur the entire transcript layer on every typed character and cursor blink, dropping framerates. Place the blur on a decoupled, non-interactive absolute backing surface (`className="pointer-events-none absolute inset-0 -z-10 rounded-[inherit] backdrop-blur-2xl"`), isolating the text input in its own layout stacking context for seamless 60/120 FPS typing.
- **Prompt History Ring & REPL Keyboard Navigation:** Implement a prompt history ring in the composer dock. Pressing `ArrowUp` when the cursor is at index 0 (or when input is empty) saves the unsent draft to a snapshot ref and navigates backward through previous prompts (`promptHistoryRef.current[idx]`). `ArrowDown` traverses forward, restoring the active draft snapshot upon returning to index `-1`.
- **Escape Priority Cascade:** Handle Escape with strict priority: (1) close open popovers -> (2) cancel history browsing & restore draft -> (3) collapse expanded input -> (4) abort active generation -> (5) blur input.
- **Slash Directive Tab Autocompletion:** Support Tab autocompletion for slash directives (`/plan`, `/build`, `/voice`, `/chat`, `/clear`).

### 3. Attachment Heap Memory Safety
- **Diff-Based Blob URL Revocation:** When managing image/file attachment previews via `URL.createObjectURL(file)`, track previous attachments in a ref (`prevFilesRef`). Diff current vs previous attachment URLs on every state change and unmount, revoking discarded `blob:` URLs immediately (`URL.revokeObjectURL(url)`). This prevents gigabytes of leaked image buffers from crashing long-lived agent sessions.

### 4. Terminal & Process Supervision Architecture
- **Native Xterm.js Canvas & PTY Integration (Zero ANSI Stripping & Mock Divs):** Terminal components in agent workbenches must integrate native `@xterm/xterm` paired with `@xterm/addon-fit` and `@xterm/addon-web-links`. Never strip ANSI escape codes (`stripAnsi`) or render terminal lines into static HTML `<div>` tags. Color formatting must be dictated purely by ANSI 256/truecolor escape codes from the PTY stream rather than brittle substring heuristics (`line.includes("200")` -> green).
- **Debounced ResizeObserver:** Resize the terminal cleanly via a debounced `ResizeObserver` (50ms debounce) that invokes `fitAddon.fit()`.
- **Per-Tab Process Abort Tracking & Cleanup:** Track `AbortController` instances in a dictionary keyed by tab ID (`abortControllersRef.current[tabId]`). Closing a tab or unmounting the component must abort running child processes immediately to prevent zombie subprocesses on the host.

### 5. Dual-Identity Session Resolution, Universal Sessions & Tombstone Filtering
- **Dual-Identity Lookup:** Support both numeric SQLite integer `id` and canonical string `session_key` (`YYYYMMDD_HHMMSS_<6hex>`) across session selection, deep links, and WebSocket notifications without identity collision.
- **Client-Side Tombstone Filtering:** When deleting sessions, maintain an in-memory client-side tombstone set (`tombstonedSessionIdsRef`) so background polling or `anara-brain-sync` refetches do not flash deleted items back into view before database operations finalize.
- **Universal Session Layer Across Views (Anara Parity):** When an agent workbench has multiple view surfaces (e.g. Chat Desktop `/` and Code Studio `/code`), all surfaces must share ONE session pool — never filter sessions by `session_type` in the list API call. A single unified localStorage pointer (`anara_active_session_id`) replaces per-surface keys (`anara_active_code_session_id`). Cross-view navigation links must carry `?session_id=<id>` so switching surfaces resumes the same conversation without creating orphan sessions.
- **Eager-Clear Stale Dependent State on Session Switch:** When the user selects a different session, immediately null out all dependent state (`workspaceTree`, `gitStatus`, `transcript`) BEFORE setting the new `activeSessionId`. Without eager-clear, React's async state batching causes stale workspace trees, git diffs, and chat transcripts from the previous session to remain visible until the new fetch resolves — creating a disorienting flash of wrong content. This mirrors Anara Desktop's `openSession()` which runs `markSessionRead()` + workspace re-scope before routing to the new session.
- **Client-Side Session Title Hydration Cache (Zero-Glitch Frame 0 Render):** In header session pickers, never use static fallback guesses like `Session #${activeSessionId || 1}`. When session lists load asynchronously over the network, frame 0 displays "Session #1" before snapping to the actual title (e.g. "Sapaan Santai") 150ms later, producing an annoying visual jump. Store the active session title in `localStorage` (`active_session_title`) alongside `active_session_id`. On page refresh, hydrate the display title directly from cache on frame 0, eliminating visual layout jitter.
- **Ghost Session URL Sanitization & Orphan Tab Purge (Post-DB Reset Hygiene):** When navigating to or mounting surfaces with `?session_id=<id>`, validate the requested ID against the authoritative session list returned from the backend. If the ID does not exist in the database (e.g. after a database wipe or deletion), immediately sanitize the URL via `window.history.replaceState` (stripping or updating `session_id`) and purge stale session IDs from client storage. If the resolved session has no attached workspace (`NO FOLDER SELECTED`), purge stale editor tabs (`ideTabs: []`, `localStorage.removeItem("anara_code_ide_tabs")`) so files from an old, detached project do not haunt the editor canvas.

### 6. Streaming Markdown Remender & Zero-CLS Scroll Pinning
- **Stream Remending vs RAF AST Parsing:** In real-time markdown streaming, parse incoming text directly using a lightweight `remendStream` helper that temporarily appends a closing code fence (`\n````) when an odd count of fences is detected. This ensures code blocks and syntax highlighters render cleanly mid-stream without waiting for final tokens and without 60Hz AST re-parsing.
- **RAF-Coalesced Direct DOM Auto-Scroll:** Auto-scroll during active streaming must use instant direct DOM assignment (`scrollContainer.scrollTop = scrollContainer.scrollHeight`) coalesced via `requestAnimationFrame`. Never call `scrollIntoView({ behavior: "smooth" })` on every token delta.
- **Auto-Scroll Dependency Must Track Content Length, Not Array Length:** When streaming updates a transcript item in-place (replacing text on an existing output bubble), `useEffect` dependencies like `[transcript.length]` never fire because the array length doesn't change. Add `lastItemText.length` (or a content fingerprint) as an additional dependency so scroll tracks growing text during streaming.
- **Passive Wheel Interruption:** Attach a passive `wheel` listener to the scroll container: any upward scroll (`deltaY < 0`) immediately disengages auto-follow mode (`isFollowingRef.current = false`) and marks incoming tokens as unread on the floating scroll-down FAB.

### 6a. Adaptive Delta Queue (Streaming Performance Pipeline)
- **Ref-Based Delta Coalescing, Not Per-Token State Updates:** Never call `setState` on every WebSocket `transcript_partial` message — fast LLMs emit 30-100+ tokens/sec, each triggering a full React render + markdown re-parse. Instead, accumulate deltas in a `useRef` string (`accumulatedRef.current += delta`) and flush to React state via an adaptive `setTimeout` (never `requestAnimationFrame` — Chromium suspends rAF for hidden/background windows).
- **Adaptive Timer Floor (3× Cost Yield):** The flush interval adapts to measured render cost: `floor = Math.min(Math.max(33ms, lastFlushCost * 3), 250ms)`. This keeps the main thread ~75% idle for user input during streaming while never dropping below ~4 updates/sec.
- **Prefer `delta` Over Accumulated `text`:** When the backend sends both `delta` (individual chunk) and `text` (full accumulated), use `delta` for incremental string concatenation in the queue. Fall back to `text` only when `delta` is unavailable. This enables future incremental rendering optimizations.
- **Flush on Turn Completion:** When the final `transcript` message arrives (non-partial, non-streaming), immediately `flushNow()` + `reset()` the queue before processing the final state update, ensuring no pending deltas are lost.
- **Visibility Change Handler:** Flush pending deltas immediately when `document.visibilityState` transitions to `"visible"` (user returns to tab).

### 6b. Incremental Block-Level Markdown Cache
- **Two-Layer Cache Architecture:** Full markdown re-parsing on every token is O(full_text) and becomes the dominant bottleneck as responses grow. Implement a two-layer cache:
  - *Layer 1 — Exact-String Cache (128-256 entries):* Map from raw markdown string to parsed `BlockToken[]` array. Returns the same array **by identity** (not just value equality), preventing downstream `useMemo` and `React.memo` from triggering re-renders on unchanged text.
  - *Layer 2 — Streaming-Append Cache (4 entries):* When new text is a prefix-extension of a recently parsed text (the streaming case), reuse the first N-2 settled blocks and only re-lex the new suffix. This turns O(full_text) into O(suffix) per token.
- **Boundary Safety:** Always drop the last 2 content blocks before reusing settled results — Setext-style headings and list continuations can merge across block boundaries when new text arrives.
- **Minimum Length Gate:** Only populate the append cache for texts ≥512 chars to avoid cache overhead on short responses where full re-parse is already fast.
- **Streaming Text Gradient Flow Animation:** Apply a flowing cyan-violet gradient on actively streaming text via `background-clip: text` with a `200% 100%` background-size animation cycling at 3s linear infinite. The gradient class (`streaming-text-gradient`) goes on the message wrapper div and is removed when `isStreaming` becomes false. Nested inline elements (`strong`, `em`, `a`, `del`, `span`) must inherit the gradient via `background: inherit; -webkit-background-clip: text`, but explicitly exclude inline code spans, carets, and badge elements from gradient inheritance to prevent visual corruption. **Note:** These CSS animations are purely cosmetic polish — they are invisible unless the underlying pipeline actually streams tokens incrementally via the adaptive delta queue (Section 6a). Adding animation classes without fixing the data pipeline is a no-op.
- **Code Block Streaming Entrance & Glow:** When `isStreamingLeaf` is true on a code block, apply a two-phase entrance animation: (1) `translateY(6px)` slide-up with 180ms cubic-bezier easing, followed by (2) alternating box-shadow glow pulse (cyan tint, 1.8s ease-in-out infinite alternate). Add a bottom mask fade (`mask-image: linear-gradient(to bottom, black calc(100% - 1.5rem), rgba(0,0,0,0.64))`) on the `<pre>` element to signal content is still arriving.
- **Arc Border on Active Streaming Message:** Wrap the streaming message div in a `streaming-arc-border` class that renders a rotating 160deg linear gradient pseudo-element (`::before`) with cyan and violet stops at 25%/75%, animating `background-position` over 2.2s. Use `mask-composite: exclude` to cut the gradient to a 1px border ring.
- **Reduced Motion Accessibility:** All streaming animations must be gated behind `@media (prefers-reduced-motion: reduce)` that disables the gradient, resets `-webkit-text-fill-color`, removes code block animations, and stops the arc border rotation.

### 7. Orchestrator Runner Cleanliness & Thinking Disclosure
- **Zero Synthetic / Fake Thought Events:** Agent execution runners and orchestrator loops must never inject synthetic or fake thought events (e.g. yielding `TurnEvent(type="thought", content="Processing request in BUILD mode with model ...")`). Fake thought events leak internal orchestration, routing paths (`9router/...`), and developer plumbing into the UI as fake AI cognition. Reasoning disclosures must be reserved exclusively for genuine chain-of-thought (CoT) tokens emitted by reasoning models.
- **Single Source of Truth for Thinking Indicators:** Never render a generic text loading placeholder (`<span className="animate-ping" /> Thinking...`) concurrently with a reasoning disclosure component (`ThinkingDisclosure` / `ThinkingCard`). The disclosure row itself is the sole indicator once CoT tokens arrive.
- **Transcript Loading & First-Token Guard (`isWaitingForFirstToken`):** Never check `!item.text` alone to render a loading or "Thinking..." placeholder in conversational chat timelines. A generic wait indicator must be strictly gated by `status === "thinking"` (or active turn streaming), restricted strictly to the latest in-flight AI turn, and only when waiting for the very first token (`isLatestAi && isTurnActive && !item.text && !item.isError && !item.interrupted`). Any empty assistant placeholder `{ speaker: "output", text: "" }` residing in an idle or settled turn must be suppressed (`return null;`) to prevent perpetual "Thinking..." ghost rows below completed messages.
- **Turn Completion Tail Pruning & Streaming Queue Reset:** Upon turn conclusion (`turn_complete`), immediately flush and reset the adaptive streaming queue (`streamFlushNow()`, `streamReset()`) and prune any trailing empty assistant placeholder bubbles (`{ speaker: "output", text: "" }`) from the transcript array.
- **Database History Restoration Sanitization:** When reconstructing transcript history from persistent storage (e.g. SQLite messages), do not promote records where `ai_text` is empty and `visual_type` is `"none"` into output bubbles. In JavaScript, `"none"` is truthy (`Boolean("none") === true`), which creates ghost assistant bubbles in restored history that trigger phantom loading indicators.
- **Visual Card In-Place Replacement & Send Filter Safety:** When visual action cards (`onAgentAction`), approval cards (`onPlanPending`), subagent cards (`onSubagentEvent`), or interactive questions arrive, they must replace any preceding empty assistant placeholder in-place (`last && last.speaker === "output" && !last.text && (!last.visualType || last.visualType === "none")`). When sanitizing previous turns upon sending a prompt, never filter out items with empty text indiscriminately (`t.text || idx === arr.length - 1`); retain items with visual card data (`t.text || Boolean(t.visualType && t.visualType !== "none") || idx === arr.length - 1`) to avoid wiping previous tool execution, diff, and question cards on subsequent prompts.

### 8. WebSocket Transport Resilience: AWS Full Jitter Backoff & 65s Liveness Watchdog
- **AWS Full Jitter Exponential Reconnect:** Never use simple additive jitter (`retry * 1000 + Math.random() * 500`) or fixed retry intervals. In production agent gateways, connection drops trigger thundering herd spikes on the backend. Implement AWS Full Jitter: calculate `temp = Math.min(maxDelay, baseDelay * Math.pow(2, attempt))`, then choose a uniformly distributed random value between 0 and `temp` (`Math.random() * temp`).
- **Connection Stability Latch (5000ms):** Never reset the reconnect retry counter immediately upon `onopen`. If a socket connects and drops after 500ms, resetting the retry counter causes rapid reconnect loops. Guard the reset with a 5000ms stability timer (`resetTimeoutRef.current = setTimeout(() => { retryCountRef.current = 0; }, 5000)`).
- **Liveness Watchdog Timer (65s):** Reverse proxies, NAT gateways, and Cloudflare tunnels frequently drop idle TCP connections silently without transmitting a TCP FIN. Complement the 30-second ping/pong heartbeat with a 65-second client-side liveness watchdog. Reset the timer on any inbound socket frame (`onmessage`); if no frame arrives within 65s, the socket is dead. Forcibly terminate the zombie connection (`ws.close(4000, "Liveness watchdog timeout")`) to immediately invoke `onclose` and trigger the backoff reconnect loop.
- **Bounded Outbound Queue with FIFO Drop:** During disconnection or connection transitions, queue outbound messages up to a strict bound (e.g. 100 frames). When the queue reaches capacity, drop the oldest frame (`outboxQueueRef.current.shift()`) to prevent unbounded memory growth during prolonged offline periods.
- **Zero-Drop Delta Streaming:** Never evaluate stream text chunks using truthy conditions (`if (msg.text)`). Empty text chunks or zero-indexed deltas are falsy in JavaScript and get discarded, truncating response words. Check explicitly: `if (msg.text !== undefined || msg.delta !== undefined)`.

### 9. Event Bus Trailing Burst Coalescing (`anara-brain-sync`)
- **Global Event Bus Debouncing:** When synchronizing state across independent components (sidebar history, dock model selection, workspace file tree, terminal tabs) via a browser event bus (`window.dispatchEvent(new CustomEvent("anara-brain-sync"))`), always debounce the listener with a trailing timer (200–300ms). Agent operations (tool executions, file writes, session updates) emit event bursts in rapid succession; coalescing ensures only a single network refetch executes per turn.

### 10. Secondary Context Surface vs Floating HUD Anti-Pattern
- **Docked Context Inspector vs Floating Modal Cards:** In autonomous coding agents, floating heads-up display (HUD) cards with saturated neon gradients and heavy drop shadows (`shadow-[0_0_35px_rgba(34,211,238,0.25)]`) are an amateur anti-pattern that occludes active conversation and IDE code. Autonomous agents prioritize docked, split-pane context surfaces (Chat Stream + Context Pane for Diffs/Files/Terminal).
- **Glanceable Passive Multimodal HUD (Voice Mode Only):** If a glanceable HUD is retained for multimodal voice interaction (displaying quick weather, document previews, or image galleries over a 3D avatar canvas), it must strictly follow Liquid Glass discipline: cosmic obsidian `#060913/90`, `backdrop-blur-xl`, hairline borders (`border-white/[0.08]`), zero raw emojis (pure SVG icons), accessible semantic buttons (`<button type="button">`), and global Escape key listeners with input element guards (`INPUT`, `TEXTAREA`, `isContentEditable`).

### 11. Multi-Tenant Context Pane & Keep-Alive Lifecycle Invariant
- **Preserved DOM Mounts over Destructive Unmounting:** Stateful context components (e.g. CodeMirror 6 code editors, Xterm.js canvas PTY terminals, visual diff viewers) must never be unmounted from the DOM when switching active context tabs (`[Files | Editor | Review | Terminal]`) or toggling the context pane collapsed. Destructive unmounting obliterates cursor positions, undo/redo history, scroll offsets, and active terminal process stdout buffers.
- **CSS Layout Hiding (`display: none` / `data-pane-hidden`):** Retain all tenant components permanently mounted inside isolated full-size containers and toggle visibility strictly using inline `style={{ display: activeTab === tabName ? "flex" : "none" }}`.
- **Post-Unhide Fit Calibration:** Terminal canvases report 0x0 geometry when hidden. Hook tab activation and layout unhiding to a deferred frame callback that triggers `fitAddon.fit()` so terminal columns and rows recalibrate instantly upon becoming visible.

### 12. Multimodal Autocomplete Popover & Live Mid-Turn Steering Protocol
- **Dual Trigger Regex Caret Parsing:** Support multimodal triggers directly in the composer input: `@([^\s]*)$` for workspace resource/file mentions and `(?:^|\s)\/([a-zA-Z0-9_-]*)$` for slash directives/skills. Dynamically calculate popover positioning anchored above the composer dock, with keyboard arrow navigation (`ArrowUp`/`ArrowDown`), `Enter`/`Tab` selection, and `Escape` dismiss.
- **Mid-Turn Steering Protocol (Anara & Anara Coding Agent Parity):** Never discard user input when the agent is busy generating or running tools (`if (isBusy) return;` anti-pattern). When `isBusy` is true and the user presses `Enter` with prompt text, dispatch a mid-turn `steer` event (`{"type": "steer", "message": text}`) to the active WebSocket session runner. This allows the user to course-correct tool selection, modify file targets, or provide instant missing feedback mid-execution without aborting the run.

### 13. Visual Review Git Diff Pane & Autonomous Ship Bar
- **Staging Lifecycle Operations:** Provide explicit visual staging controls (Stage All `git add -A`, Unstage All `git restore --staged`, and per-file stage/unstage toggles) alongside real-time insertion/deletion counts (`+N -M`) and status badges (`M`, `A`, `D`, `U`).
- **Data-Loss Safety Guard:** Destructive operations (Revert / Discard changes via `git restore`) must require explicit two-step user confirmation in the UI before discarding working tree edits to prevent accidental loss of uncommitted work.
- **Autonomous Ship Bar:** Anchor an integrated ship bar beneath the diff list containing an auto-growing commit message input (`Ctrl+Enter`), a 1-click conventional commit generator with AI (`feat(scope): ...`), split commit/push buttons, and a 1-click autonomous PR delegation action ("Ask agent to ship this PR").

### 14. V8 Heap Budgeting for Agent Workbenches (`--max-old-space-size=8192`)
- **Static Analysis Out-Of-Memory Guard:** Modern AI agent workbenches bundling CodeMirror 6, Xterm.js, Three.js, and AST parsers exceed Node.js default V8 heap limits (~1.4GB) and can easily exceed 4GB during TypeScript type checking (`tsc --noEmit`), crashing with `SIGABRT` / exit code 134 without descriptive errors. Always invoke verification and builds with explicit 8GB heap headroom: `node --max-old-space-size=8192 ./node_modules/typescript/bin/tsc --noEmit`.

### 15. Unified Agent Statusbar & Segmented Context Gauge (Anara Desktop Parity)
- **Unified 24-26px Footer Band in IDE Workstations:** Fix a unified `h-[24px]` or `h-[26px]` statusbar at the bottom of the workspace shell across full-bleed IDE code workstations (`/code`), styled with Liquid Glass cosmic obsidian (`bg-[#080A0F]`) and a 1px specular hairline divider (`border-t border-white/[0.08]`).
- **Chat Companion Dock Non-Duplication:** While a dedicated 24-26px footer statusbar is essential in full-bleed IDE code workstations (`/code`) to display workspace git status, terminal toggles, and token economics, avoid stacking a redundant bottom statusbar beneath floating composer docks in conversational companion chat interfaces. The floating composer dock already houses primary telemetry and controls (model selection, reasoning effort toggle, voice mute, send button); adding a secondary statusbar with static "No workspace" and "Gateway ready" labels crowds the bottom edge and wastes vertical reading space.
- **Telemetry & Identity Split:**
  - *Left Zone (Identity & Infra):* Drawer toggle glyph (`[◫]`), local Gateway/connection status indicator, active workspace folder badge (`📁 Project Name`), Git branch with real-time insertions/deletions diff churn (`+N -M`), and background subagent swarm counter.
  - *Right Zone (Resource & Turn Economics):* Live turn duration timer (`00:04s` active spinner during generation), segmented Context Window usage gauge (`total / max` tokens with color-coded thresholding: cyan <60%, amber 60-80%, rose >80%), active model & reasoning effort pill, mode indicator (`⚡ Smart`), build version string (`# v...`), and terminal toggle shortcut (`Ctrl+\``).
- **Segmented Context Breakdown Popover:** Anchor a click-triggered floating obsidian popover displaying segmented token allocations (Agent Core/System Prompt, Active Tools Schema, Conversation History, and Generation Output) with a clear auto-compacting threshold indicator (>85%).

### 16. Interactive Bidirectional PTY WebSocket Engine & Xterm Parsing Safety
- **Stateful Interactive PTY over Stateless Execution:** Never implement agent workbench terminals as one-shot HTTP POST / stateless command runners (`powershell.exe -EncodedCommand <cmd>`), which destroys shell state (`cd`, environment variables, virtualenv activation) and breaks interactive programs (Vim, `[y/N]` prompts, REPLs). Wire a persistent interactive subprocess with standard I/O piped bidirectional over a dedicated WebSocket (`/ws/terminal/{id}`).
- **Direct Canvas Stdin:** Never force users to type commands into a separate HTML `<input>` box below the terminal canvas. Stream raw keystrokes directly from `term.onData()` to the WebSocket, allowing full readline navigation, ANSI cursor positioning, and Tab autocompletion.
- **Xterm.js Parsing Error Silence (`logLevel: "off"`):** Xterm.js v5/v6 defaults to `logLevel: "info"`. Unrecognized vendor-specific escape sequences emitted by Windows conhost, conpty, or shell extensions (like OSC window titles or private CSI codes) trigger `this._logService.error('Parsing error: ', state)` in the browser console. Always instantiate `Terminal` with `logLevel: "off"` (or `"warn"`) and wrap `term.write(chunk)` in a safe try-catch / Blob decoder.
- **Incremental UTF-8 Decoding on PTY Chunks:** When reading raw byte chunks from subprocess stdout (e.g. 1024-byte reads), escape codes or multi-byte UTF-8 sequences can be sliced across chunk boundaries. Never decode with bare `chunk.decode('utf-8', errors='replace')` per read, which inserts `\uFFFD` replacement artifacts into escape sequences and corrupts xterm's VT500 parser. Use Python's `codecs.getincrementaldecoder("utf-8")(errors="replace")` on the streaming task to buffer incomplete byte sequences until the next packet arrives.
- **Intelligent Keyboard Shortcuts & Context Menu:**
  - Intelligent `Ctrl+C`: if text is selected, copy to clipboard; if no selection, send `\x03` (SIGINT) to the PTY stdin to interrupt the running process.
  - `Ctrl+V` / `Ctrl+Shift+V`: paste from clipboard to PTY stdin.
  - `Ctrl+F`: toggle in-terminal search overlay (`@xterm/addon-search`).
  - Right-click Context Menu: floating menu offering Copy, Paste, Select All, Clear Buffer (`term.clear()`), and Kill Process (`SIGINT`).

### 17. Floating Composer Island & Desktop Shell Navigation (Anara Desktop Parity)
- **Top Center Drag Handle:** Render a horizontal handle pill (`w-16 h-1 bg-white/20 rounded-full mx-auto`) at the top of the composer card to visually reinforce its status as an adjustable floating island.
- **Two-Tier Composer Structure:**
  - *Tier 1 (Context & Git Telemetry Strip):* Git branch badge (`🌿 main`) on the left, prompt turns counter (`↑ N`), and real-time diff insertions/deletions (`+N -M`) on the right.
  - *Tier 2 (Input & Controls):* Left attachment button `(+)`, borderless auto-expanding textarea (`"What's on your mind?..."`), and right action cluster featuring compact model chip (`[Model ⌄]`), reasoning effort pill (`[High ⌄]`), microphone button, and a solid circular send button with waveform glyph and split action chevron `( 〰 ⌄)`.
- **Top Header & Document Tab Bar (38px):** Style the top header with a distinct document tab (`● SESSION_NAME` with cyan status dot) and a `+` new tab button, flanked on the right by a window cluster (Settings, Split Context, Review Diff, Terminal, and minimize/maximize/close glyphs).
- **Segmented Studio Mode Switcher (`[SESSIONS | CODE | BOTS]`):** Cross-view navigation between Chat Sessions, Code Studio, and Bot Settings must be unified into a single segmented pill control (`[SESSIONS | CODE | BOTS]`) with a connected background container (`bg-white/[0.04] border border-white/[0.08] backdrop-blur-md rounded-lg p-0.5`). Placing `CODE` adjacent to `SESSIONS` reflects natural mode-switching between conversation and autonomous software engineering.
- **Synchronized Header Bar Heights (`h-[38px]` Standard):** Both the Chat Desktop sidebar header and the Code Studio top navigation bar must share the EXACT same container height (`h-[38px]`). Mismatched bar heights (e.g. 42px on chat vs 34px on code) cause jarring vertical layout shift during route transitions.
- **Pre-Warmed Geometry (Zero Hydration Shift):** Compute initial pill coordinates (`left: 2px` on sessions, `left: 82px` on code) on frame 0 to prevent visual snapping when DOM measurement refs resolve post-hydration.
- **Liquid Glide Navigation Deferral (140ms):** When the user clicks an alternate mode tab, allow the glowing pill to visibly glide across to the target tab (`transition-all duration-200 ease-[cubic-bezier(0.16,1,0.3,1)]`) for 140ms BEFORE executing `router.push()`. Immediate route execution cancels the animation mid-frame, causing jarring UI glitches.
- **Chrome Non-Redundancy:** Never duplicate view toggle clusters (`[Explorer | Terminal | Agent]`) in the top navigation bar when a primary vertical `ActivityBar` already exists on the sidebar. Redundant header buttons clutter the navigation space and produce dual-state synchronization bugs.
- **High-Performance CSS Variable Resizing Engine (60–144 FPS Splitters):** Never call top-level React state setters (`setSidebarWidth`) or write to cookies/localStorage on every `mousemove` event during panel drag resizing. Update the panel dimension directly on the document root via CSS variable (`--sidebar-width`) with `transition: none`, using an invisible pointer shield (`fixed inset-0 z-[99999]`), and commit to React state and persistent storage strictly ONCE upon `mouseup`.
- **Neutral Splitter Hairlines (Anti-Neon Flashes):** Splitters and resize sashes must remain understated, neutral hairline borders (`bg-white/[0.08] hover:bg-white/[0.16] active:bg-white/[0.22]`). Banning saturated neon/cyan active states (`active:bg-cyan-400`) eliminates distracting visual flashes during drag operations.

### 18. Monolithic Component Decomposition & Sub-Module Factoring (Sub-1000 LOC Standard)
- **Hard Single-File Line Cap (Sub-1000 LOC):** In complex AI agent workbenches, large orchestrator files (`CodePageClient`, `AnaraWorkbench`, `BottomDock`, `WorkspaceTreeView`, `AnaraCodeIDE`, `useWebSocket`) rapidly bloat past 1,000–1,700 lines when layout state, drag-drop sashes, context tabs, socket protocols, and AST parsing are bundled together. This causes severe developer cognitive overload, brittle edits, slow IDE IntelliSense, and elevated V8 compiler memory consumption.
- **Decomposition Blueprint:**
  - *Layout & Activity Frame:* Extract resizing sashes, collapsed sidebar states, and activity bars into dedicated hooks (`useCodeStudioLayout`) and layout shells (`CodeStudioHeader`, `ActivityBar`).
  - *Multi-Pane Orchestrators:* Isolate 3-pane code studio workspaces (`CodeStudioWorkspace`), context panes (`WorkbenchContextPanes`), and chat columns (`WorkbenchChatColumn`) into standalone components that receive explicit props and callbacks.
  - *Atomic Composer Clusters:* Break floating composer docks into atomic sub-components (`DockComposerInput`, `DockControlsCluster`, `DockStatusStack`) and dedicated hooks (`usePromptHistory`).
  - *File Tree Decomposition:* Split file explorer trees into recursive node components (`RecursiveTreeNode`), context menus (`TreeContextMenu`), and dedicated traversal hooks (`useLazyTree`, `useTreeExpansion`).
  - *Protocol & State Reconstruction:* Extract WebSocket event definitions and audio/gesture DTOs into dedicated type modules (`websocketTypes.ts`), and centralize session restoration logic into shared pure parsers (`sessionRestoration.ts`) rather than duplicating SQLite/WS transcript loops across pages.

### 19. Workspace-Scoped Project Session Grouping & Shallow Lazy Tree Explorer
- **Workspace-Bound Session Metadata:** Store workspace identity (`{name, root_path, is_external}`) directly in session records (`workspace_info_json`). In workbench sidebars, dynamically partition conversations into "Home" (unbound global chats) and collapsible "Project" groups keyed by root workspace path. Switching project folders automatically re-scopes active file trees and terminal working directories.
- **Shallow Lazy Tree Expansion (Anti-OOM Filesystem Loading):** In multi-gigabyte or deeply nested enterprise codebases, NEVER fetch or traverse the complete file tree recursively on initial load. Fetch only top-level directory entries on mount; load subdirectory contents strictly on-demand when a user clicks folder disclosure chevrons (`useLazyTree`), caching directory node sets in a reactive map.

### 20. Crash-Survivable In-Flight Turn Journaling & Cross-Session Resume
- **Storage-Backed Turn Snapshots:** When an agent turn is running, persist an in-flight snapshot (`sessionId`, `userPrompt`, `streamingText`, `liveToolProgress`, `activeTools`, `status: "thinking"`) into client storage (`sessionStorage`). Throttle writes (300–400ms) to stay off the hot streaming path.
- **Live In-Flight Folding:** When switching sessions or attaching from another client surface (e.g. mobile Telegram to desktop workspace), check for an active in-flight snapshot. Fold the journaled state onto the restored transcript bubbles (`mergeInFlightWithTranscript`) and paint the active thinking/tool indicator immediately. Clear the journal snapshot strictly upon turn completion.
- **Pitfall:** Fetching only persisted SQLite messages on session switch causes a session currently executing in the background or on another channel to render as blank and idle, leading users to believe the agent froze.

### 21. Scoped Composer Draft Stashing & Memory-Safe Attachments
- **Session-Scoped Draft Stashing:** In workbench composers, stash unsent draft text per session ID (`composer_draft_<sessionId>`) upon session change and restore it when returning to that session. Delete the stashed draft strictly upon form submission.
- **Blob Object URL Revocation:** Whenever attachments are removed, submitted, or discarded, immediately call `URL.revokeObjectURL(url)` on all `blob:` URLs to prevent multi-megabyte image leaks in browser V8 heap memory.

### 22. React-Three-Fiber (R3F) Render Priority Invariant
- **Priority 0 Automatic Render Loop:** In `@react-three/fiber`, calling `useFrame(callback, priority)` with `priority > 0` disables R3F's automatic frame rendering (`gl.render(scene, camera)`), expecting the subscriber to render manually. If no manual render is called, the canvas remains completely black or transparent. Always keep `useFrame(callback)` at default priority 0 unless implementing a full custom multi-pass post-processing pipeline.

### 23. Reasoning-Only Clean Stop Promotion & Schema-Compliant Tool Closure
- **Reasoning Content Promotion:** When reasoning models (DeepSeek-R1, Gemini Thinking, Claude Thinking) finish generation (`finish_reason == "stop"`) but leave `content` empty while populating `reasoning_content` / `thought`, promote the reasoning text directly to the visible response rather than triggering false-positive empty-turn notices.
- **OpenAI-Compatible Tool Closure (`tool_choice: "none"`):** When forcing a final narrative conclusion in conversation history that already contains `role: "tool"` messages, never strip the `tools` array completely from the API request. Omitting `tools` while `role: "tool"` exists in history triggers HTTP 400 Bad Request on strict endpoints. Pass `tools=tools` with `tool_choice="none"`.

### 24. In-Conversation Find Bar (`Ctrl+F`) & Incremental Timeline Highlights
- **Keyboard-Activated Find Overlay:** Long conversation transcripts with hundreds of turns require an in-page search overlay. Bind global `Ctrl+F` / `Cmd+F` (with input element guard) to toggle a floating find bar at the top-right of the transcript container.
- **Match Navigation & Auto-Scroll:** Show live match counters (`1 of N` or `0 matches`). Navigate matches incrementally with `Enter` / `[▼]` (next) and `Shift+Enter` / `[▲]` (previous). On step, smoothly scroll the target message into view (`scrollIntoView({ behavior: "smooth", block: "center" })`) and wrap the matched bubble in an active hairline glow ring (`ring-2 ring-cyan-400/80`). `Escape` cleanly closes the bar and clears highlights.

### 25. Code Artifact Promotion to Contextual Split-Pane (`[Split View]`)
- **Self-Contained Content Thresholding:** Detect substantial code blocks (>=48 lines or >=2,500 characters) and standalone HTML/SVG documents within assistant messages.
- **Chrome Header Split View Trigger:** Instead of forcing the user to scroll through a 500-line code block inside a chat bubble, render an explicit `[Split View]` button in the code block chrome header. Clicking it emits an event (`anara-open-code-viewer`) to dock the 50/50 contextual editor pane, opening the code as an interactive editor tab beside the conversation.

### 26. Plan Checklist Completion Linger Window (3.5s)
- **Satisfying Completion Linger:** In composer plan checklists and todo drawers, when all steps transition to completed (`isAllDone`), never dismiss the card immediately upon the final checkmark. Immediate dismissal looks like a glitch or crash.
- **Linger Window (3500ms):** Retain the completed checklist for a 3.5-second linger window (`LINGER_MS = 3500`) with green checkmarks and `X/X Completed` badge visible before smoothly auto-collapsing or dismissing the card.

### 27. Tool Observation Recovery on Empty Final Narrative & Fence Auto-Repair
- **Intermediate Observation Extraction:** When the model finishes a multi-tool execution turn without generating conversational narrative (e.g. reasoning models outputting only `<think>` blocks or bare JSON tool calls), never return an empty notice ("Belum ada respons teks..."). Fall back to extracting recent tool observations (`[OBSERVATION]`, `[TOOL RESULT]`, `exit_code`) to construct an honest completion report: `Tugas selesai dijalankan. Observasi: • <action summary>`.
- **Closed Fence Auto-Repair (`ensure_closed_code_fences`):** Output truncated mid-stream by token limits (`finish_reason="length"`) leaves orphaned code markers. Automatically check for odd counts of triple-backticks (append `\n``` `) and single backticks (append `` ` ``) before dispatching to omnichannel platforms (Telegram, WhatsApp), preventing the rest of the message from being swallowed into an unclosed code block.

### 28. Dedicated Artifacts Gallery vs Code Studio Workspace Partitioning
- **Strict Separation of Concerns:** In workbench sidebar navigation, never conflate the Code Studio workstation (`/code`) with the Artifacts Gallery (`/artifacts`).
  - *Code Studio (`/code`):* Interactive code editor, file explorer, git staging review, and terminal workstation.
  - *Artifacts Gallery (`/artifacts`):* A searchable library and gallery of all documents, images, diagrams, and files produced across all conversation sessions with filter tabs (`All`, `Images`, `Files`, `Code`), copy actions, and 1-click links back to the origin session.
  - *Capabilities (`/capabilities` / Brain):* Extensible skills catalog, tool permissions, multi-provider API keys, and omnichannel gateways.

### 29. Universal Global Command Palette (`Ctrl+K` / `Cmd+K`) Across All Views
- **Omnipresent Mounting:** The global command palette must never be bound strictly to the primary chat view. Mount the palette shell universally in both conversational workbenches and fullscreen IDE workspaces (`/code`), binding `Ctrl+K` / `Cmd+K` and `Ctrl+P` across all views.
- **Cross-Surface Navigation & Actions:** Index model switches, file explorer toggles, terminal focus, git review inspector, and session resets so users can orchestrate any workspace capability from keyboard focus alone.

### 30. Session Archiving Lifecycle & History Filtering
- **Two-Tier Session Archival:** Implement an explicit Archive action in session dropdown menus that flags records (`is_archived: 1`) without permanent deletion.
- **Archive Filter Toggle:** Provide a dedicated view/toggle in the history sidebar header to switch between active sessions and archived sessions, preventing long-lived sessions from cluttering the primary workbench drawer while preserving full retrieval and unarchival.

### 31. Ground Truth Reference Inspection over Conjecture
- **Authoritative Reference Verification:** When designing, implementing, or auditing agent architecture (slash commands, UI scaffolding, access control, or lifecycle events), always inspect the concrete reference codebase (`anara-agent`) directly as the authoritative ground truth before writing code. Never invent behavior, synthesize unsupported conventions, or make assumptions without verifying actual implementation source files first.

### 32. Sidebar Control Hierarchy & Contextual Session View/Filter Architecture
- **Vertical Navigation Hierarchy (Anti-Misplaced Header Floats):** In agent workbenches, top navigation rows (`New session` action, `Capabilities`, `Artifacts`, and the `Search sessions...` input) sit at the top of the sidebar. Directly beneath the search bar sits the `PINNED` category. The **`SESSIONS` section header (with inline action buttons: Quick New Session `+` and the View/Filter Dropdown Popover `ListFilter` / sliders icon)** must NOT float at the very top above global action buttons. It belongs directly ABOVE the main session stream, serving as the contextual control bar for the unpinned list right beneath it.
- **Unified Stream with In-Place Popover vs Rigid Tab Silos:** Avoid slicing sessions into isolated, rigid top tabs per communication platform or modality (e.g. separate tab for Telegram, separate tab for CLI, separate tab for Code). Slicing into tabs creates user cognitive friction and isolates conversation history. Maintain ONE unified session pool with an anchored dropdown filter popover (`SidebarFilterMenu`):
  - *Dynamic Grouping (Radio):* Workspace/Project root (`root_path`), Chronological Date (`Today`, `Yesterday`, `Last 7 days`, `Older`), Status (`Working` vs `Done`), or Flat (`None`).
  - *Dynamic Ordering (Radio):* Last Updated, Date Created, Total Tokens (allowing developers to immediately spot heavy context consumers), and Status Urgency.
  - *Show Badges (Checkboxes):* Fine-grained visibility toggles for compact token count badges (`1.2k`, `18k`, `1.4M`), relative timestamps, and channel lead icons (`Telegram`, `WhatsApp`, `CLI`).
  - *Channel & Project Filtering:* Quick radio filter for channel origins (`All`, `Web Studio`, `CLI`, `Telegram`, `WhatsApp`) and multi-select project checkboxes.
  - *Batch Controls:* Instant `Expand all`, `Collapse all`, and `Reset to defaults`.
- **Token Metrics Calculation & SQLite Subquery Parity:** Calculate total tokens per session either directly from token usage ledger tables (`token_usage_logs`) or through aggregated message lengths (`LENGTH(user_text) + LENGTH(ai_text) / 4`), exposing formatted monospace badges (`formatTokens`) so users can audit session context weight without opening the conversation.

### 33. Generational Frontier Model Capabilities & Dynamic Dictionary Handshake
- **Dynamic Dictionary Parsing vs Static Array Assumptions:** Modern frontier model proxies transmit model modalities as structured capability dictionaries (`{"vision": true, "imageInput": true, "reasoning": true}`). Capability detection routines must dynamically check both dictionary keys (`caps.get("vision")`, `caps.get("imageInput")`) and array elements rather than asserting `isinstance(capabilities, list)` which silently drops vision support on frontier models.
- **Open-Ended Generational Regex (Future-Proof Model Discovery):** Never hardcode static model cutoffs (e.g. stopping regex at `gpt-5` or `claude-3-5`). Use open-ended generational quantifiers (`gpt-[4-9]`, `claude-[3-9]`, `gemini-`, `qwen.*vl`) so frontier and successor models automatically inherit multimodal vision and reasoning capabilities without manual code updates.

## Diagnostic Audit Checklist

1. **ScaffoldRow Discipline:** Are conversational scaffolding items formatted as flat, quiet single-line text rows at rest (`● Thinking (1.2s) ›`, `● Edit file.ts +12 -3 ›`) with zero box backgrounds, zero borders, and zero shadows?
2. **Backdrop Blur Decoupling:** Is `backdrop-filter` kept strictly off the hot editable surface (`textarea`) and placed on an isolated `-z-10` backing surface to avoid re-blurring the entire transcript and dropping frames?
3. **Prompt History Ring:** Does the composer dock support ArrowUp at cursor index 0 to traverse history, snapshotting the active draft and restoring it upon returning, with an Escape priority cascade and Tab slash directive autocompletion?
4. **Blob URL Revocation:** Are image/file attachment preview blob URLs tracked across renders and diff-revoked on removal, send, and unmount to prevent heap memory leaks?
5. **Native Xterm.js:** Is the terminal panel implemented via native `@xterm/xterm` with `@xterm/addon-fit` debounced via `ResizeObserver` (50ms) and WebLinksAddon, with raw ANSI color rendering and per-tab abort tracking?
6. **Dual-Identity, Tombstones & Universal Sessions:** Does session resolution handle both numeric SQLite IDs and canonical `session_key` strings with tombstone sets, share a single unified session pool across all view surfaces (no `session_type` filtering), carry `?session_id=` on cross-view navigation, and eager-clear dependent state (workspace tree, git status, transcript) to `null` before setting a new `activeSessionId`?
7. **Stream Remend:** Does the markdown renderer temporarily close open code fences during streaming to prevent layout shift without 60Hz AST re-parsing?
8. **Scroll Pinning:** Does the timeline use instant direct DOM assignment during streaming rather than high-frequency smooth scrolling, disengaging on upward wheel scroll?
9. **Zero Fake Thoughts:** Are orchestrator loops free of synthetic thought events that leak routing paths and internal backend plumbing?
10. **Single Indicator Truth & First-Token Guard:** Is the generic loading placeholder hidden the instant reasoning tokens or tool execution starts, and is "Thinking..." strictly guarded by `isWaitingForFirstToken` so it never renders under settled turns?
11. **AWS Full Jitter Reconnect:** Does the WebSocket hook use AWS full jitter exponential backoff with a 5000ms stability latch to prevent thundering herd reconnection loops?
12. **Liveness Watchdog:** Is the WebSocket protected by a 65s inactivity watchdog that forcibly terminates silent zombie sockets dropped by reverse proxies?
13. **Bounded Outbox Queue:** Is the offline outbound message queue capped (<=100 frames) with FIFO eviction on overflow?
14. **Zero-Drop Delta Streaming:** Are text chunks and deltas checked with `!== undefined` rather than truthy `if (msg.text)` to prevent dropping empty or 0 deltas?
15. **Burst Coalescing:** Are event bus listeners (`anara-brain-sync`) debounced with a trailing 200–300ms timer to collapse rapid event bursts into single refetches?
16. **Docked Context vs Floating HUD:** Are code inspection, diffs, and execution plans docked into split panes alongside the chat stream rather than presented as floating modal cards with neon glows?
17. **Keep-Alive Pane Lifecycle:** Are editor and terminal components kept permanently mounted in the DOM via CSS hiding (`display: none`) to preserve cursor, scroll position, and terminal stdout history?
18. **Mid-Turn Steering Protocol:** When `isBusy` is active, does pressing Enter with text dispatch a `steer` event to course-correct the executing agent rather than silently dropping the prompt?
19. **Review Diff & Ship Bar:** Does the review pane provide file status badges, diff inspection, discard guards with confirmation, and an autonomous ship bar with AI commit generation?
20. **V8 Heap Budgeting:** Is TypeScript compilation protected with `--max-old-space-size=4096` to prevent silent SIGABRT OOM crashes in large IDE codebases?
21. **Unified Statusbar vs Chat Dock Ergonomics:** Is the footer statusbar dedicated to full IDE workstations while conversational chat interfaces rely solely on the floating composer dock to maximize vertical reading area?
22. **Interactive PTY & Xterm Parser Safety:** Does the terminal communicate via bidirectional WebSocket PTY with direct canvas input, multi-instance tabs, intelligent `Ctrl+C` (Copy vs SIGINT), `logLevel: "off"` on xterm to silence conhost escape parsing errors, and incremental UTF-8 decoding on backend chunk streaming?
23. **Segmented Studio Mode Switcher (`[SESSIONS | CODE | BOTS]`):** Are cross-view transitions between chat and code handled by a unified segmented control with a sliding indicator pill, synchronized `h-[38px]` header heights, pre-warmed frame-0 geometry, and a 140ms glide deferral before route push?
24. **High-Performance CSS Variable Resizing:** Is panel resizing driven by direct `--sidebar-width` CSS variable mutation on `mousemove` with `transition: none`, a transparent pointer shield, and single-commit persistence on `mouseup`, completely eliminating root `setState` re-renders and keeping framerates at 60–144 FPS?
25. **Neutral Hairline Splitters:** Are resize sashes styled with neutral translucent hairlines (`bg-white/[0.08] hover:bg-white/[0.16] active:bg-white/[0.22]`) with zero saturated cyan/blue active flashes?
26. **Chrome Non-Redundancy:** Are duplicate top header view toggles (`Explorer`, `Terminal`, `Agent`) removed when an active vertical `ActivityBar` is present?
27. **Turn Completion Tail Pruning:** Does `turn_complete` flush the streaming queue and prune orphaned empty assistant bubbles from the transcript?
28. **Ground Truth Codebase Verification:** Were all architectural patterns, command signatures, and access control models verified directly against reference source code before implementation?
29. **Sidebar Control Hierarchy:** Does the `SESSIONS` section header (with `+` and filter icon) sit directly above the main session stream (below the search bar and pinned items) rather than floating awkwardly above global navigation actions?
30. **Unified Session View & Filter Popover:** Does the sidebar provide in-place Grouping (Workspace/Date/Status), Ordering (Updated/Created/Tokens), Token Badges, and Channel Filtering without fracturing conversations into rigid, isolated tabs?
- **Dynamic Frontier Capabilities:** Does capability discovery dynamically parse dictionary payloads (`{"vision": true}`) with open-ended generational regex (`gpt-[4-9]`, `claude-[3-9]`) rather than static array type assertions?
